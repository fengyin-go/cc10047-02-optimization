# 实时流数据湖构建与治理平台

面向实时流数据接入、Delta湖表构建、流批一体转换、分区合并和数据治理的流式数据湖平台

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/WorkbenchView.vue|tsx  全部模块共享工作台
│   ├── src/data/modules.ts              18个业务模块配置
│   ├── src/api/              统一请求封装
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/resource.py  通用查询/导出/登记/动作接口
│   ├── app/routers/chains.py    跨模块业务链路（存储优化链路：规划→合并→汇总）
│   ├── app/services/<key>.py    每个模块独立领域逻辑
│   ├── app/services/base.py     共享服务骨架
│   ├── app/lake_storage.py      模拟湖存储：稀疏文件 + 文件版本元数据
│   ├── app/compaction_manifest.py 分区压缩执行清单结构与待办同步
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8011/api/health`

### 前端

```bash
cd frontend
npm ci
npm run dev
```

前端默认监听 `http://127.0.0.1:5175/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8011`。

## 约定

- 全部模块共享`frontend/src/views/WorkbenchView.vue|tsx`和一套资源路由。
- 每个模块仍保留独立`backend/app/services/<模块>.py`；纯前端保留
  `frontend/src/domain/<模块>.ts`，用于承载真实业务差异并维持36题位容量。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 压缩-合并执行链路

压缩任务不再只给估算组数：`domain_plan_compaction` 按每个物理分区的容量
上限（`目标大小`，如 `256MiB`）和文件实际字节数生成**分区压缩执行清单**，
挂在任务详情的 `执行清单` 字段上；「启动压缩」动作即批准清单。

- 稳定分组：分区内按文件名排序做首次适配装箱，同样的输入永远得到同样的
  分组；重新规划时已写出的组原样保留，只为剩余文件重新装箱。
- 分区合并读取清单实际产出文件（`backend/var/lake/`，稀疏文件）；每组按
  实际读取的字节数做容量阈值校验，校验结果同步到下次压缩待办，保留源
  文件版本（计划版本/当前版本）和改排原因。
- 并发执行同一计划时按任务串行，同一个文件只写一次；同名文件按
  （分区, 文件名） 确定归属，跨分区互不干扰；无版本信息的历史计划和已
  确认的产物直接兼容、采纳。
- 计划批准后若回填替换了同路径源文件，执行时检出版本冲突并改排；值班员
  从任务详情（`GET /api/compaction_task/{id}`）能看到哪些组已写出，再用
  `domain_retry_compaction` 从中断处继续。
